Evidence policy

What this remote HR portfolio documents.

Proof of work that exists in the repository, described in the language a buyer would use. This is not a client list. Emplowise has no published client case studies yet, and this page does not invent any.

  1. Repo proof or nothing.

    A shipped artifact is listed only if the code, command, or document that produces it is in the working tree. Each entry names the file or command that proves it.

  2. Behaviour over assertion.

    Where a number appears, it is the count of items in the repository, such as routes, tests, or fixtures. It is never a business result.

  3. No borrowed proof.

    No client logo, testimonial, revenue figure, award, or market size is used. Lower-tier material from the brand guidelines never appears as evidence.

  4. Honest status.

    Something pre-launch is labelled pre-launch. Something planned is labelled planned. The AI automation division is explicitly pre-launch on the public site, and it is not presented here as shipped.

Section A

Four shipped artifacts, each with repository proof.

These are the things a buyer can inspect today. Each entry names the problem it solves, the strategy behind it, what it does, and where the proof lives.

A1. Phase I web platform

Shipped
Problem
A remote HR service with published prices needs a credible public surface that works on a free host, without a server bill and without inventing proof.
Strategy
Build the site twice from one codebase: a Laravel application for the hosted environment, and a static export for GitHub Pages. Keep every public sentence in one config file so the two builds cannot drift.
Capabilities
  • 14 public routes rendered by one controller, with all copy in the configuration file.
  • A strict content security policy with a single hashed inline script, self-hosted fonts, and no third-party origins.
  • A four-step Free HR Audit wizard that validates inline, persists to SQLite, and degrades to Web3Forms or an email fallback on the static build.
  • A grounded assistant with 18 intents that answers from the same config facts, with an optional hosted model behind it.
  • EmploStart: six planned utility modules, with three job-readiness tools live here, mirrored in the browser and checked against PHP fixtures.
  • Dark mode, reduced-motion support, and WCAG AA contrast on the documented pairings.
Repo proof

A2. EmploStart: standalone, local-first career app

Shipped
Problem
Career tools that need a live API fail on a static host, and embedding heavy tool UI in a marketing site slows both products down.
Strategy
Split EmploStart into its own static app repo with six local engine modules, a Non-AI default, and consent-gated AI, then link to it from a fast launcher page on the main site.
Capabilities
  • Six modules: career pivot planning, career reimagination, market assessment, ATS resume analysis, interview prep, and profile building.
  • Deterministic local engines that make no network call, plus optional AI only after explicit consent.
  • Engine tests in the product repo, a static Pages workflow, and a launcher that discloses what runs where.
  • No account, no payment, and no advertising inside the tools.
Repo proof

A3. Free HR Audit diagnostic

Shipped
Problem
A free audit that is really a sales form wastes the buyer's time and produces nothing usable.
Strategy
Ask only what the first useful conversation needs: who you are, how many people you have, which people problems are live, and when you are available. Then hand it to a named lead with a gap map.
Capabilities
  • Four steps, about four minutes, with inline validation tied to the offending step, live progress announcements, and a busy state during submit.
  • Honeypot, throttling at 15 per minute, and server-side validation mirroring the client rules.
  • A reference number, the preferred date and slot echoed back, and a written next step.
  • Static build: Web3Forms when a key is configured, an inert form with an email fallback when it is not.
Repo proof
app/Http/Controllers/AuditRequestController.php resources/views/pages/audit.blade.php public/js/audit.js tests/Feature/SiteAndApiTest.php app/Console/Commands/ExportStatic.php

A4. 2026 brand system

Shipped
Problem
The site had grown a visual language faster than it had a written one: gradients, extra accents, and glow shadows that no document governed.
Strategy
Write the system down, reconcile it against the live CSS, and name each drift instead of pretending the CSS already matched.
Capabilities
  • An eight-swatch palette, three lockups, and clear-space and minimum-size rules.
  • WCAG pairings computed for every approved combination, including the ones that fail and why.
  • A token-by-token reconciliation that names the slate drift, the dark-only navy extension, the extra accents, the gradients, and the glow.
  • Seven Markdown sources and seven editable Office files, generated by a verifier-checked pipeline.

Section C

The case study standard, written down.

No client case study appears in this portfolio because none has been cleared for publication. A case study will be added only when all five conditions below are met. This is the standard, written down so a future case study cannot be assembled from memory.

  1. Written permission.

    The client has agreed in writing to be named, and to the specific numbers and quotes used.

  2. Baseline.

    The starting state is measured and dated before the engagement: headcount, payroll cycle time, open people issues, documentation coverage, or whichever metric the case study claims to move.

  3. Method.

    The four stages are described concretely enough that a reader can see what was installed, not just that HR was transformed.

  4. Outcome with a source.

    Any percentage or saving traces to a client record, not an estimate. If the client will not share the number, the case study uses a qualitative outcome in the client's own words.

  5. Limits.

    The case study states what did not change, how long the result held, and what the engagement did not cover.

Until then, the honest proof is the shipped platform: the code, the tests, the documents, and the published prices. Anything else would be fiction with a logo attached.
